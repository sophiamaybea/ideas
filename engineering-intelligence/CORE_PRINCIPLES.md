# Core Principles

## 1. Broken reality before products
Search for expensive friction, repeated workarounds, primitive workflows, fragmented tools, missing infrastructure, trust failures and tasks still coordinated through spreadsheets, email, PDFs, WhatsApp or manual expert labour.

## 2. Evidence → gap → reconnaissance → architecture → experiment
Do not jump from an idea to a product. Prove the gap, inspect existing technology deeply, identify the missing abstraction, compose the strongest available primitives, then design the smallest experiment that can falsify the thesis.

## 3. GitHub archaeology
For promising repositories inspect:
- exact modules/files that matter;
- architecture and data model;
- licence;
- release and commit activity;
- unresolved issues;
- dependency surface;
- security model;
- deployment burden;
- API stability;
- reusable primitives;
- what must be rewritten rather than copied.

Classify findings as **USE / FORK / EXTEND / LEARN / WATCH / REJECT**.

## 4. Compound AI, not wrapper AI
Use language models where ambiguity and synthesis matter, deterministic code where rules matter, retrieval where evidence matters, optimisation where trade-offs matter, simulation where uncertainty matters, and verification before consequential actions.

## 5. Wolfram as quantitative brain
The Wolfram layer formalises objectives, checks assumptions, estimates expected value, runs simulations, searches Pareto fronts, performs sensitivity analysis, detects hidden variables and allocates scarce capital/time/compute.

Reusable functions to pursue:
- `BuildWorldModel`
- `SearchDesignSpace`
- `FindParetoFront`
- `EstimateUnitEconomics`
- `EstimateValueOfInformation`
- `DiscoverHiddenVariables`
- `UpdateDigitalTwin`
- `GenerateExperiment`
- `OptimalStoppingPolicy`

## 6. Self-learning means measured policy change
A system is not self-learning because an LLM rewrites its prompt. The loop is:

```
observe → hypothesise → model → experiment → measure
→ analyse → propose change → backtest / sandbox / A-B test
→ promote or reject → record outcome
```

## 7. Earn-to-spend
Default initial budget: £0. Prefer open-source, local inference, free tiers and reversible experiments. Paid infrastructure must be justified by observed value or earned revenue.

## 8. Autonomous businesses are portfolios of experiments
Each business has:
- inputs;
- agent/tool graph;
- revenue model;
- costs;
- constraints;
- experiments;
- unit economics;
- confidence;
- kill/scale rules;
- reusable assets;
- an auditable event history.

## 9. Kill weak systems, preserve their knowledge
A dead venture becomes training data. Do not delete the reasoning, evidence, assets or failure causes.

## 10. Anti-slop test
Reject generic chatbots, superficial wrappers, dashboards without decisions, agents without measurable jobs, "AI for X" with no proprietary loop, and features that do not change user economics or capability.
